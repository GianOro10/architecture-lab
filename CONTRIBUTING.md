# Contributing

Contributions must add meaningful architecture value.

## Acceptable changes

- A new or improved ADR
- A reusable HLD section or example
- A concrete checklist control
- A quality, security, or documentation automation improvement
- A correction supported by a clear rationale

## Rules

1. Never publish confidential, client, employer, or proprietary information.
2. Generalize names, data, diagrams, and operational details.
3. Keep each change focused and explain the architectural value.
4. Run `python scripts/validate_docs.py` before submitting a pull request.
5. Use descriptive commit messages such as `docs(adr): add event delivery decision`.
